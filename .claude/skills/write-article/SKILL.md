# 記事作成スキル

タイトル「$0」の解説記事を大阪弁で生成し、マークダウンファイルとして保存します。

## 処理フロー

1. **CLAUDE.md から大阪弁ルールを読み込む**
   - 終助詞（やねん、やで、ん）の使い方
   - 敬語は使わない
   - 親しみやすい言葉選び
   - 避けるべき表現

2. **記事構成を決定**
   - タイトル：「$0」
   - 導入部：親しみやすく、大事な概念を簡潔に説明
   - 複数のセクション（最低5～8セクション）：
     * 「～とは何か」
     * 「基本的な使い方」
     * 「実践的な活用例」
     * 「コツ・ベストプラクティス」
     * 「よくある質問」
     * など、トピックに応じた構成
   - まとめ：重要なポイントを整理し、次のアクションを促す
   - 参考リンク：関連情報へのリンク

3. **大阪弁で記事を執筆**
   - すべてのルールに従う
   - 終助詞は「やねん」「やで」「や」を自然に混在させる
   - 「～さす」「～ん」などの大阪弁活用を使用
   - 親しみやすく、会話的なトーン
   - 技術的な正確さは損なわない
   - 複雑な概念も簡潔に説明

4. **ファイル保存**
   - ファイル名：`{title-slug}.md`（タイトルからスラッグを生成）
   - 保存場所：プロジェクトルート
   - 既存ファイルがある場合は確認を求める

## 例

```
/write-article "GitHubの使い方"
```

→ `github-no-tsukaikata.md` を生成

```
/write-article "テスト駆動開発のコツ"
```

→ `test-driven-development-no-kotsu.md` を生成

## 記事品質チェックリスト

生成した記事が以下を満たすか確認してください：

- [ ] 敬語を使っていないか
- [ ] 終助詞が自然に使われているか（「やねん」「やで」「や」など）
- [ ] 「～さす」「～ん」などの大阪弁活用が適切に使われているか
- [ ] 親しみやすく、会話的なトーンになっているか
- [ ] 技術的な正確さは損なわれていないか
- [ ] 複雑な概念も大阪弁で簡潔に説明できているか
- [ ] 段落のテンポ・リズムが良いか
- [ ] 各セクションに見出しと本文がバランスよく含まれているか
- [ ] 導入とまとめが記事全体を引き立てているか

## 注意事項

- 生成されたファイルは自動的に保存されます
- 必要に応じて手動で編集・調整できます
- `git add` `git commit` でバージョン管理に含めます
